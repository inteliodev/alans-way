# Oh My Hermes compatibility assessment

Research date: 2026-10-03. Inspected OMH **3.0.0**, pinned to [4ab239b10ae37763a774168ad25f091005c5d738](https://github.com/rlaope/oh-my-hermes/tree/4ab239b10ae37763a774168ad25f091005c5d738). This is a source review, not an installation or a live compatibility certification. No installer, setup command, updater, upstream test suite, or live Hermes configuration was executed or changed.

## Recommendation

Keep **Hermes- Alan's way** independently useful with stock Hermes. OMH makes sense as an **optional workflow pack**, particularly for substantial coding/research work, but should not become a required dependency or a default installation on the primary Telegram profile. Start with selected workflows, or pilot the native plugin in the existing `f4f` profile with its own OMH store. This recommendation follows from OMH's native integration surfaces, substantial prompt/routing behavior, memory-provider overlap, and setup's automatic child-profile synchronization described below. It is an integration judgement, not an upstream performance claim.

The examined project includes Hermes-native planning/research/review workflows, model-category routing, coding delegation, work evidence and a separate reviewed memory store. The router describes its behavior as prompt guidance; it also asks workflow-shaped requests to use OMH above other native skills. Those features can improve structured project work, but introduce another workflow owner beside the companion's native skills and existing primary. [Router skill](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/skills/omh-routing/SKILL.md), [review skill](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/skills/omh-code-review/SKILL.md), [coding dispatch](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/coding/fanout_dispatch.py).

## Does it preserve vanilla Hermes?

In the installation and native entry paths inspected, **I found no Hermes source-file rewrite or AIAgent monkeypatch**. OMH copies a standalone plugin into the active Hermes home, registers tools/hooks through `PluginContext`, uses `skills.external_dirs`, and selects its memory provider through native configuration. Its manifest requires Hermes `>=0.21.1`; the supplied stock VPS version `0.21.5` satisfies that numeric constraint. A version-range match alone does not prove every integration works. [Plugin manifest](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/plugin.yaml), [registration](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/__init__.py), [bundle installer](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/install/plugin_pack.py), [setup application](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/commands/setup.py#L1973).

It changes runtime behavior even while keeping core source stock. It registers `pre_llm_call`, `pre_tool_call`, lifecycle and result-transform hooks; it can add OMH awareness/routing/status instructions, block calls matching user tool rules, and transform outputs. The default bundle enables context injection. The optional egress feature additionally replaces configured tool handlers through native `register_tool(..., override=True)` and reads private registry-manager state. That is an opt-in runtime override, not a source patch. Leave egress, browser-adapter and group-activity extensions disabled in an initial pilot. [Defaults](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/config.yaml), [LLM hook](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/hooks/llm_hooks.py), [tool hook](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/hooks/tool_hooks.py), [egress override](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/egress_attempts.py#L223).

Some compatibility code relies on Hermes internals: duplicate-section detection reads `_manager`/`_system_prompt_sections`; browser support expects specific gateway ContextVars/cache controls. Native runtime binding requires particular profile, secret-scope, logical-working-directory and managed-config APIs and fails with `RuntimeBindingError` if required APIs are missing. These create upgrade checks even without a fork. [Registration internals](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/__init__.py#L80), [runtime binding](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/runtime_paths.py#L55), [browser boundary](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/browser_bridge.py).

## What full setup and update actually change

`cmd_setup` forces plugin installation. Its ordinary apply step can add the skill directory, enable `omh`, add a compression fallback derived from existing providers, select the branded TUI/skin, select OMH memory when the slot is unset, and bind a nondefault store. Setup also installs a TUI widget/skin and seeds model-chain preferences. Display-section collapse requires the branded-TUI confirmation or `--yes`; existing explicit settings have preservation rules. This is wider than importing one skill. [Setup](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/commands/setup.py#L2606), [configuration apply](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/commands/setup.py#L1973), [compression defaults](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/install/compression_defaults.py).

The current installer defaults to the **full** skill pack. A core pack exists, but its operational floor emphasizes managing OMH and messenger planning/status; it is not simply all the advanced coding features with lower prompt cost. The installer also notes that previously installed full-only skills are retained until explicit reconciliation. [Installer defaults](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/install/installer.py#L37), [core catalog](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/skills/catalog.py#L1406).

Most significantly, full setup and normal update walk **every directory under `<hermes_home>/profiles/`**, bootstrap new profiles, and apply native registration there. A child profile with neither an OMH setting nor `OMH_HOME` can inherit the primary's OMH store. Existing per-profile choices are preserved, but automatic enrollment is the default. Targeting a pilot at `f4f`'s own Hermes home avoids walking the primary's sibling profiles; give it an explicit separate store too. [Profile synchronization](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/commands/setup.py#L555), [profile enumeration](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/install/skill_registration.py#L184), [runtime-store documentation](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/docs/INSTALLATION.md#L14).

I found no automatic `SOUL.md` rewrite in these paths. The advisory reads that file and recommends a custom persona; generated skills explicitly defer voice/persona to it. Hermes-native model aliases are a separate digest-bound preview/apply flow requiring confirmation and a collision override when applicable. OMH still seeds and maintains its own routing/model-chain preferences. [SOUL advisory](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/maintenance/advisory.py#L608), [skill rendering](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/skills/render.py#L797), [alias adapter](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/coding/hermes_model_config.py#L145).

## Memory and existing integration overlap

Stock Hermes runs one external memory provider at a time. OMH's `set_memory_provider` refuses to replace a nonempty foreign `memory.provider` such as `honcho`. It selects OMH when that key is unset; having Honcho credentials or legacy settings alone should therefore not be assumed to protect the slot. Preserve and verify the **effective active provider** before any pilot. OMH project tools remain usable separately; selecting OMH's provider would change automatic recall away from Honcho. [Stock Hermes memory contract at d795726f78e532ca31655f74656b4be63a907581](https://github.com/NousResearch/hermes-agent/blob/d795726f78e532ca31655f74656b4be63a907581/agent/memory_provider.py), [provider-selection adapter](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/install/config_adapter.py#L1385), [OMH provider](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/memory_provider.py).

OMH's provider is deterministic and file-backed, without its own model/network calls; it supplies reviewed recall and consolidation guidance through native lifecycle callbacks. Its comparison/advisory code **does read** the active profile's built-in `MEMORY.md` and `USER.md`, although it does not directly write them. The README's broad claim that Hermes memory is never read should not be treated literally. [Provider](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/memory_provider.py), [native-memory reader](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/plugin_bundle/omh/hermes_memory.py#L133), [README memory section](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/README.md#L308).

Stores can deliberately be shared between profiles, which shares records and home-wide ledgers; this does not provide an OS sandbox. Personal recall adds principal/admission checks, but the docs acknowledge incomplete authenticated-author coverage on shared turns and the inability to isolate built-in memory already injected outside OMH. A separate f4f store is the straightforward initial boundary. [Installation/store ownership](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/docs/INSTALLATION.md#L14), [memory principal boundary](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/docs/MEMORY.md#L18).

The companion already defines a stock-Hermes MCP boundary and a primary-specific, event-driven proactivity policy. OMH's project records, loop/delegation and optional browser contracts do not establish our canonical Mac/phone handoff or Telegram delivery. Keep the companion's existing primary/session authority, Honcho choice, Mac transport and browser identity intact; use OMH only inside an explicitly selected project workflow. This is an architectural recommendation based on the two projects' surfaces, not observed interoperability. [Companion compatibility](../compatibility.md), [proactivity](https://github.com/inteliodev/alans-way-agents/blob/main/docs/proactivity.md), [continuity limits](../continuity.md).

## Opt-out, updates and a possible pilot

Useful controls exist: explicit Hermes/OMH home arguments, project scope, core/full packs, `--memory-mode off`, `--no-omh-tui`, and `--skip-apply`. The last skips configuration/profile synchronization but **still copies** plugin/widget/skin artifacts during setup. Memory off prevents OMH selection and leaves a foreign provider alone. It does not disable every plugin hook. Treat those flags as independent scope controls. [Setup options and implementation](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/commands/setup.py#L5816), [memory off](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/install/config_adapter.py#L1385).

OMH updates its own command/package and managed assets; normal update may bootstrap a never-configured home and newly created bot profiles. `uninstall --registration-only` is recognized as deliberate opt-out when the plugin directory remains. Full uninstall uses recorded changes and current-value ownership checks to reverse managed config; older unrecorded ambiguous settings can remain. Bundle replacement protects local edits/additions unless forced and distinguishes Hermes-managed installations. Thus removal/update have considered controls, but should still be verified against the chosen profile. [Update implementation](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/commands/setup.py#L436), [config reversal](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/src/install/config_reversal.py), [update/opt-out documentation](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/docs/INSTALLATION.md#L290).

If a pilot is later authorized, use a pinned revision and an explicit f4f home/store; start with memory off, current display retained, optional adapters/observers off, and the smallest useful workflow set. Verify native skill discovery, a real project turn, pause/cancel behavior, unchanged primary config/provider/route, profile-store separation, and uninstall restoration. The supplied f4f Telegram token is pending, so Telegram delivery cannot presently be a completed acceptance check. This paragraph is a proposed experiment, not an install instruction or a report that those checks passed.

## Evidence limits

Verified here: clone SHA/version, actual setup/profile-sync/defaults, plugin registration and optional overrides, memory ownership policy, alias confirmation path, and removal/update source. Read-only upstream source checks found the required runtime-cwd, managed-config and config-readability symbols at the pinned Hermes commit; the manifest's range admits 0.21.5. Those checks are static only.

Not tested: OMH loading in the VPS's actual v0.21.5 environment; coexistence with Honcho/proactive-primary; model behavior or cost; f4f store isolation during provider turns; native Mac browser integration; Telegram delivery; setup/update/uninstall restoration. The project supplies opt-in real-host tests, but its ordinary standalone suite does not exercise a live Hermes host. No performance or complete compatibility claim follows from this assessment. [Native test gating](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/tests/native/conftest.py), [runtime test suite](https://github.com/rlaope/oh-my-hermes/blob/4ab239b10ae37763a774168ad25f091005c5d738/tests/native/test_profile_runtime.py).
